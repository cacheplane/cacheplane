In `inline.ts`, locate the section handling `<` (around line 144-162). Replace the `'pending'`-discard branch with buffering:

```ts
const HTML_INLINE_PENDING_CAP = 4096;

// ... inside the inline scanner main loop, when current char is '<':

const result = matchInlineHtml(remainder, 0);
if (result === 'pending') {
  // Hold from current `<` to end of remainder. Cap at 4096 chars.
  const held = remainder;
  if (held.length > HTML_INLINE_PENDING_CAP) {
    // Overflow — flush `held` as plain text, clear pending.
    s = appendText(s, parentId, held);
    index += held.length;
    s = { ...s, htmlInlinePending: '' };
    continue;
  }
  // Hold and exit the inline scanner; next push will resume.
  return { ...s, htmlInlinePending: held, index: index + held.length };
}
```

### Task 5: HTML README DOMPurify code example (B3)

**Files:**
- Modify: `packages/partial-markdown/README.md`

- [ ] **Step 1: Locate the security section** (around line 311-315)

- [ ] **Step 2: Replace prose-only block with code example**

```markdown
### Security — sanitize before rendering

`raw` is unsanitized HTML source. Rendering it directly via
`dangerouslySetInnerHTML` is an XSS risk. Sanitize first:

```ts
import DOMPurify from 'dompurify';

if (node.type === 'html-block' || node.type === 'html-inline') {
  return <div dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(node.raw) }} />;
}
```

For untrusted streaming output where you cannot guarantee sanitization at
every render, render HTML nodes as escaped text instead:

```ts
if (node.type === 'html-block' || node.type === 'html-inline') {
  return <code>{node.raw}</code>;
}
```

Server-side / Node consumers can use [`sanitize-html`](https://www.npmjs.com/package/sanitize-html)
or [`rehype-sanitize`](https://github.com/rehypejs/rehype-sanitize) for
the same purpose.
```

```markdown
### Implementation note (0.4.0): inline math is born `complete`

In 0.4.0 the inline scanner is line-buffered: inline math nodes are created
only after the full line is available, so they are born with
`status: 'complete'`. The `streaming → complete` arc described above
applies fully to display math (`$$..$$`, `\[..\]`) but not to inline math
in the current implementation.

Identity preservation is unaffected (inline nodes are still stable across
re-pushes, since the line is committed atomically). The streaming arc for
inline math is tracked as a 0.5.0 follow-up.
```

## 0.4.1 — UNRELEASED

### Fixed

- **HTML inline pending buffer** now actually buffers `<` mid-tag content
  across separate `push()` calls. Previously, a `<spa` ‖ `n>` split between
  pushes silently dropped the partial content. Cap at 4096 chars; overflow
  flushes as plain text. `finish()` flushes any pending buffer and emits
  `unterminated_html`. (Bug since 0.4.0 introduced HTML support.)
- **Math `\\\\(` opens math.** Previously, two escaped backslashes followed
  by `\(` was incorrectly treated as plain text. Escape parity is now
  computed from the absolute input index, not the inline scanner's slice.
  (Bug since 0.4.0 introduced math.)

### Changed

- Math provider tests realigned with provider-native delimiter styles:
  OpenAI test uses `\(..\)` / `\[..\]`; Gemini test uses `$..$`.
  (Test-only; production unchanged.)

### Documentation

- README HTML security section now includes a DOMPurify code example and
  an alternative escaped-text rendering pattern.
- Math design spec gains an "Implementation note" subsection clarifying
  that 0.4.0 inline math is line-buffered (born `complete`); the
  `streaming → complete` arc applies to display math only. Tracked for
  0.5.0.
- HTML design spec updated to reflect the implementation's `htmlKind`
  field name (renamed from `kind` to avoid AST-discriminant collision).

### Tests

- Added: HTML cross-`push()` mid-tag boundary, buffer-overflow flush,
  finish-flush, `<img onerror=...>` XSS regression, kind-2 chunk split,
  kind-6 full-tag-list assertion, inline HTML in link/cell, HTML NOT in
  code spans.
- Added: math currency E2E (paragraph-tree assertions), closer-adjacency
  chunk boundary, math in heading/link/table/list/blockquote, escaped-`$$`.
- Added: link-ref partition-equivalence, `unused_link_def` absence on
  resolved refs, angle-bracket URL form.
```
